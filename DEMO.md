# CFTC Regulatory Assistant demo

A 6 to 7 minute walkthrough for a project review or recorded demonstration.

## Prepare before recording

From the project directory, start the application:

```powershell
.\start.ps1
```

If the service is already running, use the existing instance. Open http://127.0.0.1:8000 and keep this script, `README.md`, and the saved evaluation results available in the editor. Finish ingestion before recording. The current snapshot has 396 indexed passages across 13 CFTC parts; confirm the count shown by the application if the corpus has changed.

Use only the fictional examples below. Leave the part filter set to **All 13 parts** unless demonstrating the filter.

## 1. Introduce the problem and scope — 45 seconds

**Show:** The application landing screen.

**Say:**

“This is my CFTC Regulatory Assistant, a local pilot for operations analysts, reporting teams, and engineers who need to locate derivatives rule text.

“The problem is that regulatory PDFs are lengthy, and a useful answer needs an identifiable source. This application brings together section lookup, original PDF references, and a clear route to Compliance for questions requiring judgment.

“The current corpus contains 13 selected CFTC parts from the supplied 2025 PDFs. This version returns stored source excerpts. It does not yet use an LLM to produce plain-language summaries, and it does not establish the current law.”

**Do:** Open **Corpus & coverage**, point out the source vintage and snapshot, and close the dialog.

## 2. Find a section and inspect the evidence — 90 seconds

**Do:** Select the first-use acknowledgement. Enter:

> What does 45.3 require?

**Say:**

“The question passes through classification before retrieval. Because it asks about rule text, the application can search the corpus. A section number receives priority over a keyword match.”

**Do:** Submit, click the **17 CFR 45.3** citation, and show the stored passage, source version, snapshot ID, and PDF page. Click **Open original PDF**.

**Say:**

“The citation opens the stored source passage and links to the PDF page where that section starts. This lets the user inspect the evidence and its surrounding conditions. The excerpt comes directly from the indexed text rather than being regenerated by a model.

“The limits are also visible: a 2025 source cannot confirm later amendments or determine how a requirement applies to a particular transaction.”

**Do:** Return to the application and click **Helpful** to demonstrate saved feedback.

## 3. Demonstrate the safety paths — 75 seconds

**Do:** Ask:

> Is our process compliant?

**Say:**

“This requires a judgment about a specific process. The application stops before retrieval and directs the user to Compliance.”

**Do:** Click **Prepare Compliance hand-off**.

**Say:**

“The hand-off contains the question and answer reference. It is prepared and saved locally; the user copies it to an approved Compliance channel. No message is sent automatically.”

**Do:** Close the dialog and ask:

> What does EMIR require?

**Say:**

“This is outside the CFTC corpus, so the assistant declines to answer.”

**Optional:** Submit `account number 123456789`, using this fictional identifier only.

**Say:**

“Common sensitive identifier patterns are blocked, and the question is redacted in the persistent audit record. These are pilot heuristics and do not replace comprehensive data protection controls.”

## 4. Explain the implementation — 45 seconds

**Show:** The project files in the editor.

**Say:**

“The application uses a Python FastAPI backend, a browser interface built with HTML, CSS and JavaScript, and SQLite FTS5 for keyword retrieval. PDF extraction preserves section headings, source files, and page references.

“Ingestion builds a candidate snapshot in a transaction. It checks for nonempty content in all 13 parts before activating the snapshot. If that build raises an error, the transaction rolls back and the previous live index remains available. This is a structural safeguard; it is not yet the full production release gate.

“Audit records retain the question, returned sources, and pipeline version. Feedback and hand-offs link back to the answer.”

## 5. Show the evaluation improvement — 90 seconds

**Show:** `evaluation/questions.json`, then the terminal.

**Say:**

“The main review feedback was to strengthen evaluation with a held-out retrieval comparison and save inspectable, reproducible results.

“I added a frozen set of 65 retrieval questions spanning all 13 parts: 46 tuning questions and 19 held-out questions. Both splits cover every part. The held-out questions were not used to tune this comparison's ranking parameters.

“The benchmark compares BM25, citation-first BM25, lexical TF-IDF, and BM25 plus TF-IDF rank fusion against the same corpus. TF-IDF is a lexical vector baseline; this is not a comparison with neural embeddings.”

**Do:** Run:

```powershell
.venv/Scripts/python.exe -m app.evaluate
```

**Do:** Open the `results.json` at the path printed by the command. Show `manifest`, `summary`, and one entry in `per_question`.

**Say:**

“Every run saves the expected citations, ranked chunk IDs, scores, source pages, and per-question metrics. It also saves the corpus and question set, with hashes and runtime details needed for replay.”

Use the recorded results below when presenting the existing run; if inputs change, present the newly generated numbers instead.

| Method | Recall@5 | MRR@5 |
| --- | ---: | ---: |
| BM25 | 94.74% | 0.711 |
| Citation-first BM25 | 94.74% | 0.737 |
| Lexical TF-IDF | 84.21% | 0.645 |
| Hybrid fusion | 94.74% | 0.747 |

**Say:**

“Recall@5 checks whether the expected sections appear in the first five unique retrieved sections. MRR@5 rewards placing the first expected section closer to the top.

“On these 19 held-out questions, BM25 and fusion each found the expected section in 18 cases. Fusion ranked relevant results higher on average, but it did not improve recall. This small benchmark is not enough evidence to replace production retrieval.”

**Optional replay:** Demonstrate exact replay of the saved run:

```powershell
.venv/Scripts/python.exe -m app.evaluate --replay eval_runs/2026-11-07T065349830949_0000_788da2b98a/results.json
```

Expected confirmation: **Replay matched all rankings, scores, and metrics**. Replay requires the recorded runtime and unchanged evaluator and frozen inputs.

## 6. Close with the evidence and next steps — 30 seconds

**Say:**

“This demo shows source-backed section lookup, inspectable citations, classification before retrieval, local Compliance hand-offs, and saved evaluation runs. The verified test suite has 10 passing tests, including citation replay and evaluation tamper detection.

“The evaluation labels are provisional and based largely on source headings. The held-out sample is small, and source sections overlap across splits, so independent SME review and a more varied benchmark are still needed.

“The next stage is approved plain-language generation, current regulatory ingestion, SSO, and the governance controls required for a firm pilot. The present application is a local demonstration, not a compliance decision system.”

## Short description for a submission

The CFTC Regulatory Assistant is a local regulatory retrieval pilot covering 13 selected CFTC parts from supplied 2025 PDFs. It provides section lookup, versioned source excerpts, PDF page links, feedback, audit records, and locally prepared Compliance hand-offs. Questions requiring case-specific judgments are escalated before retrieval. Evaluation now includes 65 provisional questions with a frozen 46/19 tuning and held-out split, four retrieval baselines, and saved JSON bundles containing rankings, metrics, manifests, and replay inputs. BM25 and hybrid fusion achieved 94.74% Recall@5 on the 19-question held-out set; fusion achieved an MRR@5 of 0.747. These results support further development and require independent SME validation before release use.
